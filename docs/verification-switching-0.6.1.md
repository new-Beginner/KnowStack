# 0.6.1：已打开记忆侧栏时跨项目对话切换慢

> 本轮只修复切换触发及旧刷新隔离。业务逻辑仅改 `renderer/view-client.mjs`；另同步补丁版本、Renderer 握手、测试和说明。不新增权限，不改样式、原生存储、服务队列或保存核验。测试使用真实 Chromium 加载正式组件，但桥接项目是模拟数据，不冒充宿主实机测速或安装验收。

## 根因与证据

1. **切换复用页面，不重新执行冷启动。** 当前宿主按插件/视图 ID 缓存记忆页面。两个对话都选中项目记忆标签时，切换对话继续使用该页面；不是新建两份记忆存储或两份页面互相抢读。冷启动的快速路径因此不能解决已经打开页面的跟随延迟。
2. **客户端没有监听会话切换，只等1500ms轮询。** 修复前 `createViewClient` 仅由首次加载、手动重新读取或定时器发起刷新。切换不会调用前两者，目标记忆需要等待下一次轮询。测试跟踪证明主要时间花在目标读取发起之前，而不是正文绘制。
3. **旧项目待完成刷新挡住新项目。** 原 `if (pending) return pending` 不区分项目。切换时若身份/开关请求未完成，新刷新会加入旧请求。旧请求的异常又走统一清空当前选择的逻辑，因此接入即时通知时必须同时隔离旧回包，不能只增加事件监听。定向测试验证新项目可先加载，旧请求随后失败也不会清空它。

官方依据：

- [PI-Desktop 插件 API](https://github.com/vastsa/PI-Desktop/blob/main/docs/spec/07-plugins/03-plugin-api.md) 的“session follow (no extra permission)”及“Panel events”：`session:activated` 是 docked view 的公开事件，同一会话运行轮次变化也会触发；通知尽力投递，漏通知可用活动会话快照修复。跨异步操作仍须核对会话身份。
- [官方视图设计 ADR 0104](https://github.com/vastsa/PI-Desktop/blob/main/docs/adr/0104-plugin-contributed-work-panel-views.md) 及当前宿主 `plugin-view-host.ts` 的只读实现核对：页面缓存而非每次切标签销毁。宿主实现只用于定位，不调用其私有方法。

## 最小改动

`renderer/view-client.mjs`：

- 订阅公开 `pluginBridge.on('session:activated', ...)`；会话 ID/项目路径变化立即触发原有 `memory.context` 复核。不直接相信事件来授权读取或写入，也不增加会话权限。
- 请求增加代次：切换启动新代次，不复用旧项目刷新；旧上下文/开关的成功、失败和清理都不能覆盖新代次。没有强制取消原生请求、绕过后端队列或重试保存。
- 只比较会话/项目身份；同一身份的运行轮次通知不重读正文，不打断编辑。
- 保留1500ms轮询作为漏通知及开关同步兜底；卸载时解除事件监听。

`main.js`、`memory-service.js`、记忆编辑控制器、权限清单内容和样式未作本轮功能修改。项目身份复核、脏草稿保护、一次性读取令牌、保存前检查和回读不变。补丁版本由0.6.0升到0.6.1，清单与Renderer握手同步，安装包使用新文件名，旧包不覆盖。

## 复现与实机验收

在同一宿主窗口准备两个**不同本地项目**的普通对话 A/B，分别有容易区分的现有记忆；不必为测试新增或删除记忆。

1. A打开“项目记忆”，等读取结束。切到B也打开“项目记忆”，等读取结束。
2. 保持两边选中记忆标签，不关闭标签、不重载页面、不点击重新读取，在A/B间往返至少6次。
3. 修复前观察：旧项目内容短暂停留，目标记忆往往要等下一轮轮询才更新。切换发生在轮询前后不同位置，等待会不同，不能保证每次固定1.5秒。
4. 按正常插件更新流程加载0.6.1，重新建立上述两个已打开侧栏的状态，重复同样往返。目标请求应由切换通知立即驱动，不再额外等待轮询；必要的宿主核验和原生读取仍然需要时间。
5. 快速A→B→A，最终应只有A内容，晚到B结果不能覆盖A。若有未保存草稿，切换后应保留草稿并禁止误保存到目标项目；不要用重要记忆做试删。
6. 检查设置侧修改开关仍能同步、手动重新读取和冷启动仍正常。同项目会话/运行轮次通知不应无故重建正文节点。没有收到切换事件的旧宿主继续依靠原轮询，不绕过授权。

**计时口径**：记录点击对话到目标路径及正文显示的时间；如果有既有性能日志，再区分目标读取请求何时开始。采用同一机器、项目、相同记忆量，修复前后各多次，排除首次冷启动。不能把下列模拟毫秒数作为真实宿主承诺。
