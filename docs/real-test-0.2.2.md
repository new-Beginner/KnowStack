# KnowStack 本轮实机验收记录

## 结论

本轮直接调用运行中的插件，由用户实际操作设置、确认按钮与重新加载，不以模拟测试替代验收。修复版本从 0.2.0 推进到 0.2.1、0.2.2；自动与人工写入在 0.2.1 工作副本执行，最终 0.2.2 工作副本重新加载后成功回读。独立安装包安装流程未另行验收。

| 实机场景 | 直接证据 | 结果 |
| --- | --- | --- |
| 读取当前项目 | 初始返回 `missing permission: session.read.own`；修改调用后返回 `status: read`、空条目和 `autoSave: true` | 修复后通过 |
| 自动提炼与保存 | 基于已查证的权限根因生成“会话项目归属查询”；`remember` 返回 `saved`，随后独立读取取得相同 ID、标题、正文 | 通过 |
| 人工模式不提前写入 | 实际读取模式为 `false`，候选“原生记忆整表并发边界”返回 `awaiting_review`、`saved: []`；再次读取只有原有一条 | 通过 |
| 用户确认后保存 | 用户报告实际点击“保存这些记忆”并看到成功；独立读取取得两条原生记忆 | 通过 |
| 原条目保留 | 第二次保存及后续多次读取，第一条 ID、标题、正文未变化 | 通过 |
| 项目设置生效 | 用户仅将当前项目路径的覆盖值设为 `false` 并保存；实际读取模式为 `false` | 通过 |
| 重新加载后保留 | 用户重新加载插件且不改设置，回到当前聊天后读取仍为 `false`，两条记忆均存在 | 通过，需聊天 Renderer 可用 |
| 多卡查询压力 | 实机多次 `QUEUE_FULL`；针对性复现确认并发归属请求占满 8 项队列。合并同会话未完成只读请求后，实机读取恢复 | 当前场景恢复，不代表任意负载保证 |

人工设置期间有一次开关由 `false` 变为 `true`，用户不确定是否主动切换，故不将该次变化定性为缺陷。后续截图显示操作的是全局默认设置，而已有项目覆盖值优先；受控修改项目覆盖值并保存后读取为 `false`。

## 修复及证据链

1. **证据**：实机读取权限报错；只读检查已安装宿主发现 `pi.session.get()` 检查 `session.read.own`，`session.read` 用于当前工具的模型上下文。
   **发现**：项目归属查询接错 SDK 入口。
   **处理**：正式入口不再调用该 API，复用已有 Renderer 固定 `sessionGet`，限制消息读取，仅返回会话 ID、项目路径及本地来源标记；移除未使用权限，不修改宿主或访问数据库。
2. **证据**：实机多次 `QUEUE_FULL`，同会话并发查询场景修复前复现同一错误。
   **发现**：多张工具卡的归属查询可挤满队列。
   **处理**：共享同会话尚未完成的只读请求；完成后移除，后续仍重新核验，不缓存已完成快照，不合并、重试写入。

## 仍未通过或未覆盖

- 用户停在插件页面时一次读取返回 `BRIDGE_TIMEOUT`，回到当前聊天页后恢复。页面依赖的精确宿主根因尚未确认，不承诺后台任意页面都可用；不应靠盲目重试写入恢复。
- 重复提交、同主题纠正、跨会话隔离、真实并发冲突、候选拒绝/过期、插件重启进程、独立安装包安装尚未实机验收。
- 自动提炼仍由任务 Agent 执行指引，本轮成功不保证每轮必定提炼或语义去重永不出错。
- 当前项目最终实际读取的自动保存状态为关闭；后续新知识需要工具卡人工确认。
- 插件只追加，不自动改写或删除既有记忆；本轮未修改、删除已有条目。

## 回归检查的定位

语法检查、Node 回归测试和 PluginCheck 仅用于验证修复未破坏已有代码契约，不作为上表中任何实机场景的替代证据。安装包由 PluginPack 生成，版本及名称为 `dist/local.project-memory-api-probe-0.2.2.piplug`。
