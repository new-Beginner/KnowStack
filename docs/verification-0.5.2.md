# KnowStack 0.5.2 每轮首尾记忆流程验证

> 本版改动是提示词与工具描述优化，不是宿主强制执行的生命周期自动读写。安装 0.5.2 并重启 Agent 后生效；模型是否按时调用、如何判断过时与语义增量，仍需真实会话验收。

## 新流程

1. **每轮开始**：每条用户消息（包括同一聊天里的追问）先调用 `read_memory`，读取当前会话所属项目的最新记忆和自动保存模式。没有新知识也需要开场检查。
2. **检查过时项**：按原适用范围、必要条件、用户明确说明及已有已验证事实判断。只有具体证据支持的条目才报告；不因较老、未使用或暂时不适用而报告，也不为检查而无关地扫描整个代码库。不确定项原样保留。
3. **提醒用户删除**：`report_outdated_memory` 只生成提醒；用户自行检查、删除草稿并保存。Agent 不通过工具、Shell 或界面代删。最终回答保留 `finalReminder` 原文及标记，复用 0.5.1 的最终回复卡片。
4. **每轮结束**：评估本轮是否存在已验证、可长期复用的新知识。有候选才重新读取最新记忆并按含义和适用条件去重；开场凭据 5 分钟后失效，不能默认沿用。
5. **保存**：有真正增量且自动保存开启时直接调用 `remember`，不逐条询问；用户关闭自动保存时仍进入人工确认，不擅自打开开关。无新知识不调用写入、不凑条目；保存后等待回读结果，最终回答据实说明。

读取失败或没有可访问本地项目时，不把失败解释为空记忆、不声称检查通过、不提交没有有效读取依据的报告或保存；可继续的主任务不被无关阻塞。未验证写入不盲目重试。

## 重复检查

在项目根目录运行：

```bash
for f in *.js renderer/*.mjs tests/*.cjs; do node --check "$f"; done
node --test tests/*.test.cjs
git diff --check
```

再使用 PI-Desktop 的 `PluginCheck(directory=".")` 与 `PluginPack(directory=".")`，生成 `dist/local.project-memory-api-probe-0.5.2.piplug`。版本、Renderer 握手和安装包文件名保持一致，未增加权限，旧包不覆盖。本轮保留先前工作区未提交改动，没有创建 Git 提交或推送。

## 安装验收

1. 安装 0.5.2 并重启当前会话 Agent；确认插件注册版本、工具描述及开场指引已更新。
2. 在本地测试项目发送普通问题，再追问一次。即使没有新知识，两轮均应先读取原生记忆；没有具体过时证据不生成删除提醒，没有新知识不写入。
3. 手动添加一条可丢弃测试规则，并明确告诉 Agent 该规则已经废弃。下一轮开场应对该具体条目生成只读提醒，在最终回答下方可见；原记忆仍存在。
4. 在自动保存开启时明确一个新的、长期有效的测试项目约定。检查收尾重新读取、去重、调用 `remember` 并回读成功；下一轮重复同一约定不重复保存。测试完由用户自行清理，不由 Agent 代删。
5. 手动关闭自动保存，给出另一条新约定；检查仍为 `awaiting_review`，Agent 不擅自打开开关或模拟点击。
6. 长任务超过 5 分钟时，收尾使用新的读取凭据。提醒、保存失败时不能宣称完成，跨项目和并发保护沿用现有机制。
