# 更新日志

## 0.3.3

安全加固（自查）。

- 拒绝硬链接：`.workflow` 下指向项目外文件的硬链接此前能被读出并附加到模型请求（符号链接的防护对硬链接无效）。现在只读取单链接的普通文件。
- FIFO 等特殊文件不再被读取；打开文件时带 `O_NONBLOCK`，不会因为 FIFO 卡住对话。
- 单个知识文件上限 256KB，单次检索最多读取 2000 个文件，超出的跳过。
- 提示注入防护：自动附加的块、`load` 结果和系统提示都说明条目是"项目数据而非指令"；附加时 ID、标题、摘要分别截断到 80/120/120 字符。
- 移除 `fs.delete` 权限：面板处理过的暂存建议改为标记已处理，不再删除。

## 0.3.2

安全修复（插件中心对 0.3.1 的审核意见）。

- 0.3.1 每次文件操作都重新对工作目录做 realpath 来确定项目根。如果两次操作之间项目目录被改名，原路径换成指向另一个项目的符号链接（或另一个目录），自动检索会读到另一个项目的知识并附加到模型请求中。
- 现在会话开始时（`session_start`，或首次使用时）固定项目根：记录真实路径和目录的 dev/ino。之后所有读、列目录、写、删都只使用这个固定路径，并在操作前后核对工作目录仍指向同一目录；不一致时拒绝，已读取的内容丢弃，已写入的文件撤回。
- 固定按"会话 + 工作目录"区分：新会话会重新固定，项目被正常移动或重建后不会一直被拒绝。
- 新增回归测试：固定后把根目录替换为指向其他项目的符号链接、替换为另一个真实目录，确认外部内容不会进入发给模型的请求，也不会写入其他项目。

## 0.3.1

安全修复（插件中心对 0.3.0 的审核意见）。

- 当 `.workflow`、`.workflow/knowhow` 或 `.workflow/specs` 本身是符号链接时，Agent 扩展可能读到项目外的 Markdown，并把命中摘要附加到模型请求中。现在每一级路径组件（包括起始目录）都拒绝符号链接，要求真实路径位于项目内，文件用 `O_NOFOLLOW` 打开并核对 inode。
- `readText`（替代或关联旧条目时使用）经过同样的检查。
- 写入先写 `O_EXCL|O_NOFOLLOW` 临时文件，写入前后都校验目录的规范路径，再在同一目录内改名。
- 测试覆盖起始目录、嵌套目录、目标文件为符号链接，以及通过符号链接路径打开项目的情况。

## 0.3.0

以 `axc00.project-knowledge` 首次公开发布。

- 每条消息自动检索相关的 knowhow / spec 条目，每轮的第一次及后续模型请求都会附带，且各轮之间内容逐字节一致（不破坏提示词缓存）。
- 提供 `search`、`load`、`propose` 三个 Agent 工具。
- 只有用户在聊天中的 `asktool` 卡片上作答后才会保存；答案读取自宿主返回的结果，而不是模型。
- 可选 Jev 去重（默认关闭），失败时回退到标题/内容规则。
- 备用面板用于处理未作答的建议。
- 界面跟随应用语言，支持英文和简体中文。

更早的版本（0.1.x–0.2.x）是以 `local.project-knowledge` 为 ID 的私有构建。安装本插件前请先卸载它，否则每条消息会被附加两次知识。
