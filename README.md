## 开始使用

1. 加载当前项目根目录，或安装 `dist/local.project-memory-api-probe-0.6.3.piplug`。
2. 授予清单中的权限；升级后的新权限不能仅靠热重载自动获得。
3. 开始一个 Agent 会话，或重启已有会话的 Agent，使新的扩展指引生效。工具目录也可能需要下一轮消息刷新。
4. 每轮开始读取最新原生记忆并复用长期事实。收尾有真正新知识才重新读取、去重保存；同主题事实改变用 `update_memory` 保持原 ID。明确失效且模型删除开启时用 `delete_memory`，关闭时只生成用户检查提醒。
5. 在工具卡核对实际保存结果。自动模式成功后，指引要求 Agent 在最终回复末尾附上实际保存的标题和正文。

安装时沿用旧 ID `local.project-memory-api-probe`，以升级现有诊断插件，而不是额外安装一份。显示名称已改为“知栈 · KnowStack”。

**0.3.1 界面修复：** 插件页 KnowStack 行右侧的齿轮打开项目开关弹窗。宿主 `openLayer()` 挂载点为 0×0，0.3.0 的绝对定位遮罩未正确覆盖视口；0.3.1 改为固定定位，并按宿主结构补测。若插件页仍显示 v0.2.2，请安装新的 0.3.1 包更新宿主注册版本；磁盘源码版本变化不代表注册版本已更新。详见 [修复验证](docs/verification-0.3.1.md)。

## 在右侧工作面板管理记忆

1. 打开右侧工作面板的 **新建（＋）**，点击 **项目记忆**。这是宿主正式侧栏标签页，不打开窗口或全屏遮罩；可与浏览器一样切换标签。
2. 顶部显示当前宿主选中会话的项目与路径，项目栏只读。无草稿时随项目变化读取；已有脏草稿时保留并锁定保存，确认“重新读取”后才切换。
3. **自动保存新记忆** 和 **允许模型删除记忆** 即时持久化，与插件设置共用同一项目配置，约 1.5～2 秒核对同步。开关不会写入正文。修改功能始终开启，没有开关。
4. 可手动添加、编辑标题正文或点击线框垃圾桶；删除确认只修改草稿，不受“模型删除”开关限制。点击 **保存记忆** 后才提交并回读，正文不可为空。
5. 保存冲突、会话归属变化或结果不确定时保留草稿并停止提交；先重新读取核对，不盲目重试。切换侧栏标签保留已加载页面状态；宿主关闭/驱逐视图或 reload 可能销毁未保存草稿，操作前先保存。
6. 没有活动本地会话、远程项目或上下文不可核对时停止读写，不回退任意项目。当前正式侧栏需要活动会话，不支持无聊天项目编辑。

**0.4.3 输入焦点修复：** 删除记忆和放弃草稿改用编辑器内确认，不再打开系统 `window.confirm()`，避免系统模态框影响聊天输入焦点。确认框默认聚焦“取消”，支持 Esc 取消；确认删除仍只是修改草稿，保存后才生效。如果旧版聊天框暂时无法输入，可先切换侧边栏内容恢复，再安装新版。真实宿主修复效果尚待安装验收，详见 [验证记录](docs/verification-0.4.3.md)。

侧栏通过 `pluginBridge` 的本插件限定通道查询宿主 `session.getActive()`，由后台复核选中会话；原生读写仍复用固定可信 Renderer 通道及同一串行队列，不修改宿主、不动态加载宿主模块、不直接访问数据库。历史提醒的“定位编辑器”保留原来独立的用户确认流程。

## 删除关闭时：提醒用户检查

每条用户消息开始时（包括同一聊天里的追问），Agent 先读取最新原生记忆并检查过时项；任务中出现新证据时再复核。检查不等于必须报告：仅在有具体依据时提交疑似过时报告；只因记录较早、近期没用或暂不适用，不应建议删除。没有证据的条目原样保留，不为检查而无关地扫描整个代码库。读取失败不能当作空记忆，也不声称已检查通过；不阻塞可继续的主任务，不另起后台巡检模型。

1. 最终回复下方显示琥珀色“知栈 · 过时记忆待检查”卡片，列出具体条目和原因；原文与依据可展开。操作按钮靠前，不依赖工具记录展开。报告本身不修改、删除、替换、归档或屏蔽原生记忆。
2. 点击 **打开记忆并定位**：重新核验发起会话、所属项目和原文，然后打开固定到提醒所属项目的编辑器并高亮目标条目；不会自动删草稿或保存。已有编辑器打开时先关闭，避免丢失草稿。
3. 如果确认该记忆已过时，由你点击目标条目的删除按钮并确认；此时只改草稿。再点击 **保存记忆** 才真正删除，保存后回读验证。
4. 点击 **本次忽略** 不改动记忆。同一会话、同一项目、同一原文在本次插件加载期间只提醒一次，换说法或换轮次也不会重新提醒。不同会话独立判断。
5. 提醒操作有效期为 15 分钟；重载插件后旧卡片不可操作，不跨会话建立待办或第二套记忆库。聊天历史可能保留旧报告文本，但不代表提醒仍有效。
6. 目标记忆已修改或已不存在时，旧提醒不能继续定位；会话换项目、项目组变化时停止操作。自动保存开关只管新记忆，**永远不授权自动删除**。
7. 成功报告返回 `finalReminder`，Agent 须将其原样附在最终回答末尾（不得放进代码块）。其中独立 HTML 注释标记只关联真实报告 ID；`entryExtra` 用宿主传入的会话 ID 重新读取提醒，无须工具卡先挂载。无标记的普通回复不展示卡片，跨会话复制标记不能读取原报告。
8. 未加载插件或模型漏掉标记时，原生卡片无法挂载；最终文字提醒可作为降级展示。重载后旧卡片只提示失效，不恢复临时报告。多条或长内容可能受宿主附加区高度限制，使用宿主“展开完整内容”查看，不影响运行记录的折叠状态。

建议在测试项目手动添加“提醒测试：本项目继续使用已废弃的旧构建配置”之类的临时记忆，然后明确告知模型它是已废弃测试规则，并要求只报告、不要代删。检查卡片出现后原文仍在，再自行验证忽略、定位、草稿删除和保存。不要用重要记忆试删。

## 切换自动或人工保存

- 插件设置中每个项目分别提供 **自动保存**、**模型删除** 两个开关；默认值只初始化新项目，已有项目选择保持不变。多文件夹项目的各根路径保持一致。
- 自动保存默认开启；模型自主删除默认关闭，升级不会擅自启用。修改始终开启，无开关。只有删除开关授权模型的 `delete_memory`，自动保存不授权删除。
- 启动或加载插件时扫描本地项目；会话变化和每 2 秒核对项目列表。新增项目自动补齐，删除项目清理对应设置；打开设置页也会刷新。扫描失败不会把原列表当成空列表清除。
- 仍可在记忆工具卡中切换 **本项目自动保存**，与设置页共用同一份配置。扫描、修改开关串行保存，不写入或删除项目记忆。
- 关闭后，候选显示“待确认 · 尚未保存”。点击“保存这些记忆”才写入，点击“不保存”或不作答都不写入。
- 人工候选只暂存在本次插件进程中，15 分钟后过期；重载后失效，不会自动补写。打开自动开关也不会追溯补写旧的人工候选。
- 项目模式配置只包含路径到布尔值的映射，不包含记忆内容，不构成第二套知识库。最多保留 200 个路径设置。

界面示例（模拟项目）：[桌面截图](docs/settings-0.3.0.png) · [窄屏截图](docs/settings-0.3.0-narrow.png)。

**兼容边界：** 当前宿主没有自定义设置插槽。插件使用 Renderer 层和仅针对自身插件行的设置按钮适配，不修改宿主源码；若将来宿主更改插件页 DOM，适配可能需要更新。原生基础设置中已移除 JSON 字段，即使适配失效也不会再次要求手填项目记录。远程项目不纳入本地记忆开关列表。

同一项目的会话共享宿主原生记忆；绑定会话是为了确定写入目标、核验来源和反馈结果，不是为每个会话建立独立记忆库。

## 什么内容值得保存

保存可跨聊天长期复用的项目仓库 URL、权威资料位置、不可越过的约束、稳定决策与技术条件；会话索引必须说明“哪段对话主要记录什么、去哪查（已核对的会话 ID/标题或持久文档路径）”。不存阶段总结、任务完成清单、例行测试结果、临时路径、猜测、密钥或已有结论。不会批量迁移、改写或清空历史真实记忆。

- 标题目标 6～16 个汉字，安全上限 24 个字符。
- 正文目标 1～3 句话，上限 300 个字符。
- 每批最多 3 条；允许零条，没有最低数量要求。
- 太长时重新提炼，不机械截断。插件会拒绝超限输入，并对明显的凭证格式做有限拦截；这不替代模型的敏感信息判断。

> 原生记忆接口保存完整条目列表。新增前须重读并保留其他条目，保存后回读验证；保存前比对不能完全消除并发覆盖风险。

## 去重与写入保护

1. 宿主在 Agent 启动时读入原生项目记忆，不是每轮实时刷新。插件不重复全量注入旧知识块。
2. 每轮开场均调用 `read_memory` 获取最新条目、项目模式及读取凭证；收尾若有新知识候选，再读取一次，比较语义与适用条件，不能沿用可能过期的开场凭证。
3. `remember` 必须携带同一会话、同一轮的有效凭证；凭证 5 分钟后失效。
4. 本地拦截相同正文、同标题候选及批内重复；语义判断仍依赖模型。同主题事实变化不能追加冲突卡片，改用带证据的 `update_memory`。
5. 保存前核对发起会话和唯一项目组、比较两次快照；变化则停止。队列在异步读取开关前同步占用任务，避免两个渲染器重复领取。
6. 追加、修改、删除和手动编辑均保存后回读；修改保留原 ID 与其他条目，删除只移除指定 ID。任何可能写入的响应丢失都标为不确定，阻止继续写入，不回滚、不重放。
7. 原生条目 ID 由规范化正文的哈希稳定生成；同一请求不会因为重复投递就不断新增。

**保证边界：** 每轮开场检查和收尾提炼由任务 Agent 执行扩展提示词，不是宿主强制生命周期读写；不能承诺模型绝不漏调用、一定有新知识或所有同义改写都能识别。没有另起后台总结模型，也不额外调用外部审核服务。插件内队列串行执行，但不能阻止其他窗口／插件在检查与保存之间修改整表，或在最后一次核验后移动会话；底层接口没有原子比较并保存能力。

## 查看保存结果与处理失败

| 状态／代码 | 含义与处理 |
| --- | --- |
| `saved` | 已完成写入和回读，工具卡展示实际保存的标题与正文 |
| `updated` / `deleted` | 原 ID 更新／指定条目删除已回读验证 |
| `AUTO_DELETE_DISABLED` | 模型删除未开启，不写入；可报告提醒，不替用户开启 |
| `HOST_*` + `errorStep` | 安全宿主错误码及失败接口；仅明确瞬态只读错误最多重试一次，任何写入均不重放 |
| `awaiting_review` | 尚未保存，等待真实用户点击工具卡 |
| `skipped` | 重复或已存在同主题；普通重复不显示空卡片 |
| `STALE_BASIS` / `CONCURRENT_CHANGE` | 记忆已变化；重新读取并判断增量，不原样重发 |
| `SESSION_MOVED` / `PROJECT_MEMBERSHIP_CHANGED` | 会话或所属项目组变化，旧请求停止 |
| `UNSTRUCTURED_MEMORY` / `NONCANONICAL_MEMORY` | 旧式正文或无法安全保留的结构，拒绝自动转换和覆盖 |
| `unverified` | 保存可能已经发生但无法验证；检查原生记忆，不重新提交，不自动删除／回滚 |
| `PREVIOUS_WRITE_UNVERIFIED` | 本次插件加载内该目标被阻止继续写入，先人工核对原生记忆 |
| `RENDERER_NOT_READY` / `BRIDGE_TIMEOUT` | 检查插件权限、Renderer 加载及宿主版本；超时若可能发生写入，按不确定结果处理 |

人工确认发生在最终文字回复之后时，原回复“待确认”不会被回写；工具卡更新为真实保存回执。它是最终状态依据。故障状态和待审核状态绝不能标为“已保存”。

不确定结果的阻止状态、读取凭证和待审核候选均为临时状态。重载不会证明上次保存成功或失败，不能用重载作为绕过检查、盲目重试的理由。

## Agent 工具

工具通过 ToolSearch 激活，完整名称保留旧插件 ID 前缀：

| 工具 | 输入 | 作用 |
| --- | --- | --- |
| `plugin_local_project_memory_api_probe_read_memory` | `{}` | 根据可信执行上下文读取当前会话的原生项目记忆；返回 `readToken`、条目和当前模式 |
| `plugin_local_project_memory_api_probe_remember` | `readToken`, `items[]` | 提交真正的新记忆；自动保存或等待工具卡确认 |
| `plugin_local_project_memory_api_probe_report_outdated_memory` | `readToken`, `items[{memoryId,reason,evidence}]` | 只生成最多 3 条疑似过时提醒，不修改原生记忆 |
| `plugin_local_project_memory_api_probe_update_memory` | `readToken`, `items[{memoryId,title,content,evidence}]` | 始终可用的原 ID 修改，最多 3 条 |
| `plugin_local_project_memory_api_probe_delete_memory` | `readToken`, `items[{memoryId,reason,evidence}]` | 只在模型删除开关开启时按证据自主删除，最多 3 条 |

所有 Agent 写入目标均来自宿主可信 `sessionId` / `turnId`，不能由模型指定其他项目。新条目只接受标题和正文；修改/删除必须使用当前读取中真实存在的 ID、同轮 5 分钟有效凭据和具体证据。提醒工具本身仍无删除行为。证据是否充分及长期价值仍需模型判断，字符串校验不能保证语义质量。

## 权限、数据和运行入口

| 权限 | 用途 |
| --- | --- |
| `agent.tool.register` | 注册读取、追加、修改、删除及只读报告工具 |
| `agent.extension` | 注入固定的提炼／去重／回执指引，不读写文件知识库 |
| `renderer.extension` | 真实确认卡、项目开关及固定内部 IPC 记忆读写 |
| `ui.view` | 在宿主工作面板内展示本插件的正式记忆侧栏；不授予文件、网络或额外会话读取权限 |

没有文件读写、网络、`session.read.own` 或 `desktop.control` 权限。项目归属查询与保存前后核验统一复用 Renderer 内部固定 `sessionGet` 通道，限制为 1 条消息、1 字符内容；仅向插件服务返回会话 ID、项目路径和本地来源标记，消息正文不回传 Agent，也不用于提炼。0.2.0 误用了需要 `session.read.own` 的 `pi.session.get()`；`session.read` 实际仅用于当前模型上下文，不能授权该 API。实际记忆内容只来自原生记忆接口。不开启任意 IPC、直接数据库写入或宿主源码修改。

| 文件 | 作用 |
| --- | --- |
| `main.js` | 正式插件入口，注册工具与 Renderer 回调 |
| `memory-service.js` | 会话凭证、项目开关、保存队列、人工确认状态 |

| `renderer/project-controls.mjs` | 固定项目列表读取、事件与定时核对、设置状态 |

node --check main.js

node tests/outdated-cdp.cjs
node tests/settings-cdp.cjs
node tests/docked-cdp.cjs
node tests/switching-cdp.cjs

然后使用 PI-Desktop 的 `PluginCheck(directory=".")` 与 `PluginPack(directory=".")`，生成 `dist/local.project-memory-api-probe-0.6.3.piplug`。不要手工压缩安装包。CDP 脚本需要本机 Chrome，可通过 `CHROME_PATH` 指定可执行文件；只操作模拟数据。运行前设置 `PI_SCRATCH_DIR`、`TMP`、`TEMP`、`TMPDIR` 到本会话 scratch，设置 `KNOWSTACK_SCREENSHOT_DIR` 控制截图位置。`theme-cdp.cjs` 验证知栈青叶/浮影主题、默认回退及实时切换；`switching-cdp.cjs` 验证跨项目往返；`settings-cdp.cjs` 验证双开关、设置入口与滚动保持，`docked-cdp.cjs` 验证正式侧栏组件、图标操作、明暗主题和窄栏；其余浏览器脚本验证原删除确认/提醒流程。
